# 多语言电商扩展调研：法国／德国本地语言场景

## Context
- 本文仅为调查与方案设想，不是实施授权；本轮未修改代码，未运行测试或实站验证。
- 用户已确认：法语商品名在法国网站找商品；德语商品名在德国网站找商品。英语输入搜索法国网站等跨语言检索不在范围内。
- 因此核心问题是现有英语优先规则能否正确处理当地语言，而不是翻译商品名。默认保留当地语言原文，不新增翻译服务或跨语言查询链路。
- 本文取代此前的 `plans/multilingual-expansion.md` 讨论草案；后续修订以本文件为准。

## 调查发现
以下来自只读代码核查，不代表已经通过法德真实商品验证。

### 已有可复用能力
| 环节 | 已有能力 | 位置 |
|---|---|---|
| 搜索地域 | DDG 已有 de/fr 地域映射；Serper 使用 gl | `src/search/providers/duckduckgo.py`、`serper.py` |
| 查询 | 原商品名配合零售商、site: 等变体，可直接查询当地语言 | `src/search/layers/query_builder.py::build_queries` |
| 数字规格 | 已有小数逗号市场配置及 Stück、lot de、boîte de、Zoll、pouces 等规则 | `src/search/layers/numeric.py::extract_numerics`、`src/search/maintain/search_config.yaml` |
| 品牌 | 去重音归一化、字面／模糊匹配；证据缺失保留 UNKNOWN | `src/search/utils.py::normalize`、`src/search/layers/brand.py` |
| 身份判断 | matching 可将 Unicode 原文、属性和规则证据送入 LLM；有效相同 GTIN 可直接确认；可选视觉证据 | `src/matching/service.py` |
| 抓取 | Decimal、独立 currency 与不同价格类别；Amazon 法德域名已有路由，部分德语属性映射 | `src/scraping/models/product_data.py`、`src/scraping/hosts.yaml`、`src/scraping/scrapers/sites/amazon_uk.py` |

### 明确的实现边界
1. **search 与 matching 数量规则不一致。** `src/matching/attributes.py::extract_multipack` 仍偏英文和点小数，未复用 search 的数字分隔符归一化。这是优先级最高的适配候选。
2. **地域不等于独立语言控制。** 所读 Serper 查询路径有 gl，未见 hl；这不是搜不到法德商品的证据。先测本地原文查询，不默认增加参数或输入字段。
3. **小数格式有歧义。** search 对逗号后三位数字保留逗号，`0,750 l` 需要定向测试；不能仅靠统一替换逗号和句点解决所有情况。
4. **价格类型依赖上游契约。** Amazon `_to_decimal()` 直接转换数值字符串，不是 locale 解析器。若上游返回标准数值则无需修改；若返回 `19,99` 或 `1.299,00 €` 则需要适配。
5. **属性与库存映射需核对。** Amazon 显式属性映射已有部分英德词，未列法语 taille/couleur；库存使用布尔转换，需确认上游实际返回布尔值而非字符串。

### 待验证风险，不视为已确认故障
- quantulum3 对法德单位全称、法国 Go/To、不换行空格的覆盖情况。
- 德语名词首字母大写与品牌启发式冲突，或品牌词表中的普通词碰撞。
- 去重音、变音和 ß 等规范化是否增加误匹配；检索归一化不能取代原文证据。
- 法德口味、颜色、无糖／无酒精等区分属性的 LLM 判断质量。
- 法德促销／库存文本、单位价与售价、会员价、地区配送状态的抓取效果。
- 英文提示词本身不是模型不支持法德语的证据，不据此直接更换模型或翻译提示词。

## Approach：推荐方向

### 1. 保持本地原文搜索，不建设翻译链路
- 法语输入直接搜法国目标站，德语输入直接搜德国目标站。
- 复用国家映射、site: 与查询变体；先测召回，再决定是否需要同语言词形、缩写或同义词扩展。
- 不把翻译模型、向量数据库或多语言代理作为首期必需组件。

### 2. 优先统一结构化规格语义
- 将不同写法归一到相同属性：件数、单件容量、总量、尺寸、存储容量等。
- 区分单件规格和包装总量，不能因为总量相同就判定同一商品。
- 研究复用／抽取 search 已有能力，避免在 matching 再维护一套逐渐分叉的语言正则。
- 无法识别时保留 UNKNOWN，不将“不理解当地表达”当成确定冲突；明确识别出的规格差异仍应保留判别力。
- 品牌、型号、GTIN 保留原文和精确标识；不因语言适配放宽所有硬规则。

### 3. 增量补充语言／地区规则，不复制整条流水线
- 共用搜索、抓取、匹配流程，按需增加法德数字格式、单位／包装词和属性别名。
- 区分语言、数字格式、币种与站点契约；首期可由已知市场配置确定，不为理论上的组合立即扩展公共 API。
- 品牌词表优先增加有证据的当地品牌／别名，不把所有法德词汇都做成词典。

### 4. 复用现有 LLM，针对真实错误改提示或模型
- 先让现有模型直接比较同语言原文；用正负样例测口味、型号、颜色、包装等细粒度区别。
- 只有实测显示瓶颈时再调整多语言说明、添加少量示例或比较不同模型。
- 视觉为包装／属性补充证据，不是搜索漏召回或前置误杀的补救手段。

### 5. 把新站接入与语言适配分开
- 页面结构、反爬、数据源字段属于站点问题；小数、单位、库存表达属于语言／地区问题。
- 优先验证已有 Amazon 法德路由，再选择实际业务目标站；不能从 Amazon 可路由推断所有法国／德国电商已可抓取。
- 价格优先读取结构化标准数值；只在真实上游返回当地格式文本时引入 locale 解析。

## Verification：未来 PoC 建议
- 仅评测法→法、德→德；英→英作为回归，不投入跨语言组合。
- 样例包括完全同款、描述不同但规格相同、近似型号、不同口味／颜色、不同件数／单件容量、缺失字段。
- 规格等价：`6 × 330 ml` 与 `lot de 6 bouteilles de 33 cl`。
- 规格冲突：`6 × 330 ml` 与 `12 × 330 ml`；相同总量但单件／件数不同。
- 格式覆盖：`0,75 l`、`0,750 l`、`1.000 g`、`1 000 g`、`55 Zoll`、`55 pouces`、`128 Go`。
- 抓取覆盖：`19,99 €`、`1.299,00 €`、会员价／单位价；`En stock / Rupture de stock`、`Auf Lager / Nicht verfügbar`。
- 分环节记录搜索召回、规则误拒、最终误接受／漏匹配、价格和库存字段准确率，并记录成本与延迟。
- 无法检索、无法抓取和确定非同款分别计数，避免用一个端到端数字掩盖故障来源。
- 先测基线再定验收阈值；不宣称未经实测的法德语准确率。
