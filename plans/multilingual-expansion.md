# 法国／德国电商扩展：讨论草案

## Context
- 当前仅做方案设想，不实施代码改动。
- 目标是识别英语／英国为主的样例迁移到法国、德国时的风险；先明确输入语言与同款口径，再决定工程范围。
- 首轮已读 `src/search/CLAUDE.md`：已有 country 参数、搜索引擎国家映射、跨 TLD 域名匹配、品牌去重音能力、数字规则和最终 LLM 判定；不等于全链路已支持法德语。

## Approach（初步推荐，待讨论）
- 不采用全量翻译替换原文。保留原文证据，以结构化属性归一化为基础，按需增加当地语言查询，最后用多语言 LLM 处理语义差异。
- 国家、语言、站点、币种分开建模；国家选择不等于搜索语言设置。
- 先建英／法／德小型标注评测集，定位召回、硬规则误杀、抓取解析、最终判定各环节的问题，再做最小适配。
- 商品型号、GTIN、品牌、数量与单位优先使用可解释规则；翻译不改写标识符，不覆盖原始商品名。

## Files to modify（候选范围，非实施承诺）
- `src/search/layers/query_builder.py`：当地语言查询与原始查询的组合策略。
- `src/search/layers/numeric.py`：数字、单位、包装数量的语言适配。
- `src/search/utils.py`、`src/search/maintain/brand.xlsx`：品牌别名与规范化边界。
- `src/matching/attributes.py`：核查并补齐与 search 数量规则之间的能力差距，优先评估共用归一化逻辑。
- `src/scraping/scrapers/sites/amazon_uk.py`：核查上游价格、库存字段类型和法语属性名；只有真实响应需要时才增加适配。
- 共享输入模型与测试的具体范围待需求确认。
- 若未来改变配置或维护流程，同步更新相应模块 README。

## Verification（未来 PoC 设想）
- 输入语言 × 目标站点语言分组评测：英→法、英→德、法→法、德→德及用户需要的组合。
- 正负样例覆盖重音／变音、德语复合词、小数逗号、包装规格、地区版本、不同口味与近似型号。
- 分别衡量召回率、规则误杀率、最终误匹配率／漏匹配率、价格解析正确率、成本和延迟。
- 英国现有样例作为回归基线；不预设未经实测的准确率或阈值。

## 只读核查补充
- 子代理核查发现：search 配置已经包含小数逗号市场及 `Stück / lot de / boîte de / Zoll / pouces` 等规则，因此应先评测，不重复建设。
- matching 的 `extract_multipack()` 仍偏英文、点小数，与 search 存在明确能力落差；推荐优先讨论统一数字／包装语义，而不是先换 LLM。
- 搜索查询当前不做翻译；DDG 已有法德地域映射，Serper 使用 `gl`，所读路径未见独立 `hl`。是否需要语言控制须结合搜索服务语义与召回实测判断。
- Amazon 法德域名已有路由；Decimal、currency 与价格类别已有结构。其 `_to_decimal()` 并非 locale 字符串解析器，但上游若返回标准数字便不构成问题。法语 `taille/couleur` 的显式映射需要核查补齐。
- `0,750 l`、法国 `Go/To`、德语品牌误提取、库存文本、单位价／售价混淆列为重点评测项，不能视为已实测故障。
- 英文提示词不等于模型无法处理法德语；多语言模型和视觉路径可先复用并评测。
- 具体样例：`6 × 330 ml` 与 `lot de 6 bouteilles de 33 cl` 应等价；与 `12 × 330 ml` 应冲突。相同总量不自动表示相同包装商品，最终以用户同款口径为准。
